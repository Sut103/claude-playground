# Task: スキャフォールド、DOM 契約、テストハーネス

## Description

以降の全タスクが前提とする「契約」を確定させる。具体的には ① `index.html` の全 DOM コンテナ ID、② `window.RT` 名前空間、③ マッチレコードのデータ形（AD-2）とそのフィクスチャ、④ `file://` で開ける単体テストランナーの 4 つ。

このタスクが並列化の前提条件になる。ここで ID とデータ形を確定させておくことで、フェーズ 2 の 6 タスクは `index.html` に触らず、評価コアの完成も待たずに実装できる（AD-6）。逆にここが曖昧なまま並列実装に入ると、`index.html` の同時編集と契約の食い違いで確実に破綻する。

機能ロジックは一切実装しない。空の名前空間と、開いて動くテストランナーだけを用意する。

## Technical Details

**名前空間の初期化** — 二重読み込みに耐える形にする。

```js
// src/namespace.js
window.RT = window.RT || {};
```

**マッチレコードのフィクスチャ** — AD-2 の形に厳密に従う。`participated` フラグが `undefined` と `""` を区別することを、フィクスチャの段階で表現しておく。

```js
// tests/fixtures.js
window.RT_FIXTURES = {
  single: { ok: true, truncated: false, matches: [
    { index: 4, end: 9, match: "hello", groups: [], named: [] }
  ]},
  adjacent: { ok: true, truncated: false, matches: [
    { index: 0, end: 2, match: "ab", groups: [], named: [] },
    { index: 2, end: 4, match: "cd", groups: [], named: [] }
  ]},
  zeroWidth: { ok: true, truncated: false, matches: [
    { index: 0, end: 0, match: "", groups: [], named: [] }
  ]},
  unparticipatedGroup: { ok: true, truncated: false, matches: [
    { index: 0, end: 1, match: "a", groups: [
      { label: "$1", value: "a", participated: true },
      { label: "$2", value: undefined, participated: false },
      { label: "$3", value: "", participated: true }
    ], named: [] }
  ]},
  namedGroup: { /* ... */ },
  empty: { ok: true, truncated: false, matches: [] }
};
```

**テストランナーの登録方式** — フェーズ 2 の 6 タスクが `tests/unit.js` を同時に編集する。各タスクが自分のセクションを**追記のみ**する規約にするため、登録は関数呼び出しの列にする。追記位置が異なれば git が自動マージできる。

```js
// tests/assert.js が提供する API
RT_TEST.suite("segments", function (t) {
  t.deepEqual(actual, expected, "隣接マッチが 2 セグメントに分かれる");
});
```

**`tests/run.sh`** — Playwright の Node API を使う（AD-5）。`@playwright/test` は解決できないため使わない。

```bash
#!/bin/bash
export NODE_PATH=/opt/node22/lib/node_modules
node "$(dirname "$0")/run-unit.js"
```

**DOM 構造の方針** — ハイライト領域は `<pre>` にして改行と連続空白を保持する（FR-2.5）。`white-space: pre-wrap` を併用し、長い行が横にはみ出さないようにする。
