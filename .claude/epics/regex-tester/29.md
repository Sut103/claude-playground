# Task: マッチエンジン

## Description

パターン文字列とフラグ文字列を受け取り、テスト文字列に当てて構造化した `MatchOutcome` を返す純粋モジュール `src/logic/matcher.js` を実装する。

このモジュールが US-1（マッチ）・US-2（フラグ）・US-3（キャプチャ）の中核であり、Worker からも Node のテストからも import される。DOM にも Worker API にも一切触れない。

## Acceptance Criteria

- [ ] `src/logic/matcher.js` が `runMatch(pattern, flags, input)` を export し、`MatchOutcome` を返す
- [ ] 不正なパターンに対し `{status:"error", message}` を返す（例外を投げて呼び出し側に伝播させない）
- [ ] エラーメッセージが `RegExp` コンストラクタの例外内容を含み、人間が原因を判別できる
- [ ] `g` フラグなしのとき、マッチは最大 1 件
- [ ] `g` フラグありのとき、全マッチが出現順に並ぶ
- [ ] 各 `MatchResult` が `value` / `start` / `end` / `groups` を持ち、`end` は排他インデックス
- [ ] 番号付きグループが `number` 昇順で `groups` に並ぶ
- [ ] 名前付きグループの `name` が設定される（無名グループは `null`）
- [ ] 捕捉されなかったオプショナルグループの `value` が `undefined` になり、空文字列 `""` と区別できる
- [ ] ゼロ幅マッチ（`(?=x)` や `a*` の空マッチ）で無限ループに陥らない
- [ ] `u` フラグ有効時の不正エスケープがエラーとして報告される
- [ ] `y` フラグ有効時に `lastIndex` の挙動が正しく扱われる
- [ ] `test/matcher.test.js` が上記すべてを網羅し `node --test` で通る

## Technical Details

**シグネチャ**:

```js
/**
 * @param {string} pattern
 * @param {string} flags
 * @param {string} input
 * @returns {import("./types.js").MatchOutcome}
 */
export function runMatch(pattern, flags, input) {}
```

**ゼロ幅マッチの扱い**: `g` フラグ付きで `RegExp.prototype.exec` をループさせる場合、空文字列にマッチすると `lastIndex` が進まず無限ループする。マッチ長が 0 のときは `lastIndex` を明示的に 1 進める。この境界は必ずテストで固定すること（`/a*/g` に `"bb"` を当てる等）。

**グループの抽出**: `exec` の戻り値は配列風オブジェクトで、添字 1 以降が番号付きグループ、`.groups` が名前付きグループの辞書。名前と番号の対応は `.groups` の値と添字の値を突き合わせて求める。同じ値を持つ別グループがあり得るため、値の一致だけで対応付けるのは誤り — パターンから名前付きグループの出現順を読み取るか、`exec` 結果の `groups` と番号の対応をパターン解析で決める。実装が複雑になる場合は、名前付きグループの名前をパターン文字列から `(?<name>` の出現順で抽出し、番号付きグループの出現順と突き合わせる方式を採る。

**`y` フラグ**: sticky は `lastIndex` からの一致のみを許す。`g` と同時指定された場合の挙動も含めテストする。

**禁止事項**: `document` / `window` / `localStorage` / `self` への参照を書かない。
