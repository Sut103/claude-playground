# Task: 履歴の永続化モデル

## Description

使用したパターンとフラグの履歴を保存・読み出し・消去する `src/logic/history.js` を実装する。US-5 に対応する。

`localStorage` を直接触らず、ストレージを引数で注入する形にする。これにより Node のテストからインメモリの偽ストレージを渡して全経路をテストできる。この注入が AD-2（ロジック層の環境非依存）の具体例になる。

## Acceptance Criteria

- [ ] `src/logic/history.js` が `loadHistory(storage)` / `addEntry(storage, entry)` / `clearHistory(storage)` を export する
- [ ] ストレージは `getItem(key)` / `setItem(key, value)` / `removeItem(key)` を持つオブジェクトとして受け取る（`localStorage` 互換）
- [ ] `addEntry` が `HistoryEntry`（`pattern` / `flags` / `savedAt`）を保存する
- [ ] 同一の `pattern` + `flags` の組を再度追加したとき、重複を作らず既存エントリを先頭へ繰り上げる
- [ ] 履歴は新しい順に並ぶ
- [ ] 上限件数を超えたとき、最も古いエントリが捨てられる
- [ ] `clearHistory` が保存内容を消去し、以後 `loadHistory` が空配列を返す
- [ ] 保存領域が空のとき `loadHistory` が空配列を返す（例外を投げない）
- [ ] 保存内容が壊れた JSON のとき `loadHistory` が空配列を返す（例外を投げない）
- [ ] 保存内容が JSON として妥当でも配列でない場合に空配列を返す
- [ ] `setItem` が例外を投げる状況（容量超過等）で `addEntry` が呼び出し側に例外を伝播させない
- [ ] `test/history.test.js` がインメモリの偽ストレージを使い上記を網羅、`node --test` で通る

## Technical Details

**シグネチャ**:

```js
/** @typedef {{getItem(k:string):string|null, setItem(k:string,v:string):void, removeItem(k:string):void}} StorageLike */

/** @returns {import("./types.js").HistoryEntry[]} */
export function loadHistory(storage) {}

/** @returns {import("./types.js").HistoryEntry[]} 更新後の履歴 */
export function addEntry(storage, entry) {}

export function clearHistory(storage) {}
```

**上限件数**: モジュール内の定数として定義し export する（UI から件数を表示できるように）。20〜50 程度の範囲で決めること。

**壊れた保存内容への耐性**: `localStorage` の中身はユーザや他のスクリプトが書き換え得る。`JSON.parse` は必ず try/catch で囲み、パースできても配列でない・要素が期待の形でない場合を弾く。ここを落とすとアプリが起動しなくなるため、テストで固定する。

**保存キー**: 衝突を避けた明示的なキー名を定数として定義する（例: `regex-tester:history`）。

**最終状態の復元について**: US-5 には「最後の入力内容（パターン・テスト文字列・フラグ・置換文字列）を復元する」という受け入れ基準もある。これは履歴とは別の関心事（履歴はパターンとフラグのみを持つ）。同じモジュール内に `saveSession` / `loadSession` として同じ storage 注入方式で実装し、テストを付けること。テスト文字列は長大になり得るため、保存サイズの上限を設けるか、`setItem` 失敗時に黙って諦める方針を決めてテストに残す。

**禁止事項**: `document` / `window` / `localStorage` への直接参照を書かない。ストレージは必ず引数経由。
