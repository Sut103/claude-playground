# Task: セグメント変換と HTML エスケープ（純粋関数）

## Description

マッチレコード列とテスト文字列から、描画可能なセグメント列を組み立てる純粋関数 `RT.buildSegments(text, matches)` を実装する。加えて `RT.escapeHtml(str)` を提供する。

AD-4 が定めた分割の前半にあたる。「どこが何色か」という判断はここで完結させ、DOM 生成タスク（004）には「セグメントの列」しか渡さない。ハイライトの境界条件——隣接マッチ、幅ゼロマッチ、文字列先頭・末尾のマッチ、マッチなし——の正しさはすべてこのタスクの単体テストで担保される。DOM を立ち上げずに検証できるため、境界条件を網羅しやすい。

DOM に触らない。`document` を参照しない（TC-1）。

## Acceptance Criteria

- [ ] `RT.buildSegments(text, matches)` が `[{ kind, text, matchIndex }]` の配列を返す。`kind` は `"plain"` / `"match"` / `"empty"` のいずれか（FR-2.1）
- [ ] セグメントの `text` を順に連結すると元の `text` に一致する（`kind: "empty"` は `text: ""` なので連結に影響しない）
- [ ] `matchIndex` が `"match"` / `"empty"` セグメントに 0 始まりのマッチ番号を持ち、`"plain"` では `null` になる
- [ ] マッチが 0 件のとき、`text` 全体を含む単一の `"plain"` セグメントを返す（FR-2.6）
- [ ] `text` が空文字かつマッチ 0 件のとき、空配列または空の `"plain"` 1 件を返し、後段が例外を出さない
- [ ] 隣接する 2 マッチが 2 つの独立した `"match"` セグメントになり、間に空の `"plain"` を挟まない（FR-2.3）
- [ ] 文字列先頭から始まるマッチの前に空の `"plain"` セグメントを生成しない
- [ ] 文字列末尾で終わるマッチの後に空の `"plain"` セグメントを生成しない
- [ ] 幅ゼロマッチ（`index === end`）が `kind: "empty"`、`text: ""` のセグメントになる（FR-2.4）
- [ ] 文字列末尾の幅ゼロマッチ（`index === text.length`）が正しく `"empty"` として現れ、脱落しない
- [ ] 連続する複数の幅ゼロマッチが、それぞれ独立した `"empty"` セグメントになる
- [ ] `RT.escapeHtml(str)` が `&`, `<`, `>`, `"`, `'` を対応する文字参照に変換する（FR-2.2）
- [ ] `RT.escapeHtml` が `&` を最初に変換し、二重エスケープを起こさない（`"<"` → `"&lt;"`、`"&lt;"` → `"&amp;lt;"`）
- [ ] `RT.escapeHtml(undefined)` および `RT.escapeHtml(null)` が例外を投げず空文字を返す
- [ ] `document` および `localStorage` への参照が存在しない（TC-1、grep で検証）
- [ ] IIFE でラップされ `window.RT` 以外のグローバルを作らない（TC-2）

## Technical Details

**変換の骨格** — カーソルを進めながらマッチの隙間を埋める。

```js
(function (RT) {
  RT.buildSegments = function (text, matches) {
    var segments = [];
    var cursor = 0;

    for (var i = 0; i < matches.length; i++) {
      var m = matches[i];

      if (m.index > cursor) {
        segments.push({ kind: "plain", text: text.slice(cursor, m.index), matchIndex: null });
      }

      if (m.end === m.index) {
        segments.push({ kind: "empty", text: "", matchIndex: i });
      } else {
        segments.push({ kind: "match", text: text.slice(m.index, m.end), matchIndex: i });
        cursor = m.end;
      }
    }

    if (cursor < text.length) {
      segments.push({ kind: "plain", text: text.slice(cursor), matchIndex: null });
    }
    return segments;
  };
})(window.RT);
```

**注意点**

- 幅ゼロマッチでは `cursor` を進めない。進めると後続の `plain` が 1 文字欠ける
- `m.index > cursor` の判定を `>=` にすると、隣接マッチの間に空の `plain` が入る。AC の「空の plain を挟まない」がこれを検出する
- 幅ゼロマッチと通常マッチが同じ位置に混在するケース（`g` 付き `a*` を `"ab"` に適用すると index 0 で `"a"`、index 1 で `""`、index 2 で `""`）を必ずテストする
- マッチは評価コアが返す時点で位置の昇順に並んでいる前提を置く。ソートし直さない

**エスケープの実装** — 順序が重要。

```js
RT.escapeHtml = function (str) {
  if (str === undefined || str === null) return "";
  return String(str)
    .replace(/&/g, "&amp;")
    .replace(/</g, "&lt;")
    .replace(/>/g, "&gt;")
    .replace(/"/g, "&quot;")
    .replace(/'/g, "&#39;");
};
```

`&` を先に置かないと `<` → `&lt;` の `&` が後段で再変換され `&amp;lt;` になる。

なお 004 の DOM 生成は `textContent` を使うため（AD-4）、`escapeHtml` は実際の描画経路では使われない。`innerHTML` を使う実装への将来的な差し戻しに備えた保険と、FR-2.2 の明文化された要求への対応として実装する。**このタスクの成果物が使われないことを 004 が前提にしてよい**、という点を認識しておく。

**テストの置き場所** — `tests/unit.js` の `RT_TEST.suite("segments", ...)` セクションに追記する。
