# Task: UI 結線と描画

## Description

これまでのモジュールを結線し、ブラウザ上で動く形にする。入力の購読、デバウンス、Worker への評価依頼、結果の描画、履歴 UI、セッション復元をここで組み上げる。

描画は `innerHTML` を使わず、テキストノードと要素生成のみで行う（AD-5）。テスト文字列はユーザ入力であり、HTML として解釈させない。

## Technical Details

**ファイル分担**:

- `src/ui/render.js` — DOM 生成のみ。セグメント列 → ハイライト要素、マッチ配列 → 表、エラー・タイムアウト表示。状態を持たない
- `src/ui/app.js` — 入力購読、状態保持、デバウンス、`worker-client` 呼び出し、`history.js` への保存、`render.js` への受け渡し

**デバウンス**: 入力のたびに Worker へ投げると、暴走パターンの生成→terminate を高頻度で繰り返すことになる。停止を検出してから評価する。値は定数として持つ。

**履歴への記録タイミング**: 一文字打つたびに履歴が積み上がると使い物にならない。「有効なパターンで、かつ入力が一定時間止まったとき」あるいは明示的な保存操作のときに限る。方針を決めてコメントに残すこと。

**セッション復元**: `history.js` の `loadSession` を起動時に読み、入力欄へ流し込んでから初回評価を走らせる。復元値が壊れている場合は空状態で起動する。

**`localStorage` の注入**: `history.js` は storage を引数で受け取る。`app.js` が `localStorage` を渡す唯一の場所になる。ここ以外で `localStorage` を参照しないこと。

**描画の制約**: ハイライトは `document.createElement("span")` + `document.createTextNode(value)` で組む。キャプチャ表のセルも同様。`undefined` の表示は文字列 `"undefined"` を出すのではなく、値が無いことが分かる専用のスタイルを当てた表現にする（空文字列 `""` の表示と区別が付くこと）。
