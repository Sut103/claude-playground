# Task: 永続化とフォールバック

## Description

パターン・テスト文字列・フラグ・置換文字列を localStorage に保存し、起動時に復元する `RT.saveState(state)` / `RT.loadState()` / `RT.clearState()` を実装する。FR-6 の全項がここに閉じる。

このタスクの本質は**失敗経路の設計**にある。`file://` から開いた場合、localStorage へのアクセス自体が環境やブラウザ設定によって例外を投げることがある。保存データが壊れていることもある。いずれの場合もアプリを起動不能にせず、初期サンプル状態にフォールバックしなければならない（FR-6.3 / FR-6.4）。SC-7 はこの経路を直接検証する。

初期サンプルの内容もこのタスクで決める。初回起動時にツールの動作が一目で分かるパターンとテスト文字列を仕込む（FR-6.3）。

## Acceptance Criteria

- [ ] `RT.saveState(state)` が `{ pattern, flags, text, replacement }` を localStorage の**単一キー**に JSON として保存する（FR-6.1）
- [ ] `RT.loadState()` が保存済みの 4 項目を復元して返す（FR-6.2）
- [ ] `RT.loadState()` が保存データ無しのとき、初期サンプル状態を返す（FR-6.3）
- [ ] 初期サンプルにパターンとテスト文字列が入っており、そのままでマッチが 1 件以上発生する（ツールの動作が初見で分かる）
- [ ] 初期サンプルのフラグに `g` が含まれる（複数マッチが見える状態で開く）
- [ ] `RT.loadState()` が壊れた JSON（例: `"{oops"`）に対して例外を投げず初期サンプルを返す（FR-6.3）
- [ ] `RT.loadState()` が JSON として妥当だが型が違うデータ（例: `"[]"`, `"null"`, `"42"`, `'{"pattern":123}'`）に対しても例外を投げず初期サンプルにフォールバックする
- [ ] 一部のキーが欠けたデータ（例: `'{"pattern":"a"}'`）で、欠けた項目のみ初期値を補い、存在する項目は復元する
- [ ] `flags` が文字列でない、または `gimsuy` 以外の文字を含む場合、不正な文字を捨てるか初期値に倒す（`new RegExp` に不正フラグを渡すと例外になるため）
- [ ] localStorage が利用不可な環境で `RT.saveState` が例外を投げずに静かに失敗する（FR-6.4）
- [ ] localStorage が利用不可な環境で `RT.loadState` が例外を投げず初期サンプルを返す（FR-6.4）
- [ ] `RT.clearState()` が保存内容を削除し、以降の `RT.loadState()` が初期サンプルを返す（FR-6.5）
- [ ] `RT.clearState()` が localStorage 利用不可な環境でも例外を投げない
- [ ] IIFE でラップされ `window.RT` 以外のグローバルを作らない（TC-2）

## Technical Details

**全アクセスを try/catch で包む** — localStorage は「存在するのに読み書きで例外を投げる」ことがある。存在チェックだけでは足りない。

```js
(function (RT) {
  var KEY = "regex-tester.state";

  var DEFAULTS = {
    pattern: "(\\w+)@(\\w+)\\.com",
    flags: "g",
    text: "連絡先: alice@example.com, bob@test.com\n無効: carol@localhost",
    replacement: "$1 [at] $2"
  };

  function defaults() {
    return { pattern: DEFAULTS.pattern, flags: DEFAULTS.flags,
             text: DEFAULTS.text, replacement: DEFAULTS.replacement };
  }

  function sanitizeFlags(f) {
    if (typeof f !== "string") return DEFAULTS.flags;
    var out = "";
    for (var i = 0; i < f.length; i++) {
      if ("gimsuy".indexOf(f[i]) !== -1 && out.indexOf(f[i]) === -1) out += f[i];
    }
    return out;
  }

  RT.loadState = function () {
    var raw;
    try {
      raw = window.localStorage.getItem(KEY);
    } catch (e) {
      return defaults();                       // FR-6.4
    }
    if (raw === null || raw === undefined) return defaults();

    var parsed;
    try {
      parsed = JSON.parse(raw);
    } catch (e) {
      return defaults();                       // FR-6.3
    }
    if (parsed === null || typeof parsed !== "object" || Array.isArray(parsed)) {
      return defaults();
    }

    var d = defaults();
    return {
      pattern:     typeof parsed.pattern     === "string" ? parsed.pattern     : d.pattern,
      text:        typeof parsed.text        === "string" ? parsed.text        : d.text,
      replacement: typeof parsed.replacement === "string" ? parsed.replacement : d.replacement,
      flags:       sanitizeFlags(parsed.flags)
    };
  };

  RT.saveState = function (state) {
    try {
      window.localStorage.setItem(KEY, JSON.stringify(state));
    } catch (e) { /* FR-6.4: 静かに失敗 */ }
  };

  RT.clearState = function () {
    try {
      window.localStorage.removeItem(KEY);
    } catch (e) { /* 同上 */ }
  };
})(window.RT);
```

**注意点**

- `typeof parsed !== "object"` だけでは `null` と配列を弾けない。`JSON.parse("null")` は `null` を返し `typeof null === "object"` なので、明示的に除外する（AC が `"null"` と `"[]"` を要求しているのはこれを検出するため）
- `sanitizeFlags` は重複も除去する。`"gg"` を `new RegExp` に渡すと `SyntaxError` になる
- `u` と `v` は排他だが、`v` は対象フラグに含まれないため問題にならない
- キーは 1 個。項目ごとに別キーにすると、部分的に書き込まれた中間状態が生まれる（FR-6.1 が単一キーを要求している理由）
- 保存の頻度制御（debounce）は呼び出し側（008）の責任。このタスクは呼ばれたら保存するだけ

**テストの置き場所** — `tests/unit.js` の `RT_TEST.suite("storage", ...)` セクションに追記する。localStorage 利用不可の状況は、`window.localStorage` の `getItem` を一時的に throw する関数へ差し替えてテストする（テスト後に必ず復元する）。
