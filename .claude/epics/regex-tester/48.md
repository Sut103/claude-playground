# Task: E2E スイートと NFR 検証

## Description

Playwright で `file://` からアプリを開き、6 ユーザーストーリーと非機能要件を検証する `tests/e2e.spec.js` を実装する。PRD の SC-2〜SC-9 と epic の TC-1〜TC-3 がここで判定される。

このタスクが epic 全体で最も不確実。性能（SC-5: 100ms）と無限ループ耐性（SC-3: 5 秒）は実測するまで達成可否が分からず、未達なら 003 / 004 への差し戻しが発生する（epic のリスク節）。工数に L を積んでいるのはこの差し戻し込みの見積り。

## Technical Details

**骨格** — 素の Playwright API + 自前の assert。

```js
const { chromium } = require('playwright');
const path = require('path');

const APP = 'file://' + path.resolve(__dirname, '..', 'index.html');
let failures = [];

async function scenario(browser, name, fn) {
  const page = await browser.newPage();
  const pageErrors = [];
  const external = [];
  page.on('pageerror', e => pageErrors.push(e.message));
  page.on('dialog', async d => { failures.push(`${name}: unexpected dialog`); await d.dismiss(); });
  page.on('request', r => { if (!r.url().startsWith('file://')) external.push(r.url()); });

  try {
    await page.goto(APP);
    await page.evaluate(() => localStorage.clear());
    await page.reload();
    await fn(page);
    if (pageErrors.length) failures.push(`${name}: pageerror ${pageErrors[0]}`);
    if (external.length) failures.push(`${name}: external request ${external[0]}`);
    console.log(`  ✅ ${name}`);
  } catch (e) {
    failures.push(`${name}: ${e.message}`);
    console.log(`  ❌ ${name} — ${e.message}`);
  } finally {
    await page.close();
  }
}
```

**性能計測（SC-5）** — 入力から描画完了までを測る。`input` イベントを発火させ、`.rt-match` の数が期待値になるまでを計測する。

```js
const elapsed = await page.evaluate(() => {
  const el = document.querySelector('#test-text');
  const t0 = performance.now();
  el.value = BIG_TEXT;
  el.dispatchEvent(new Event('input', { bubbles: true }));
  return performance.now() - t0;    // 同期描画なら戻り時点で完了
});
```

`update()` が同期実行なら `dispatchEvent` の戻り時点で描画は終わっている。もし将来 `requestAnimationFrame` などで非同期化されたら、この計測方法は嘘になる。その場合は `waitForFunction` で描画完了を待って計測に切り替える。

**XSS 検証の要点** — `window.__XSS__` の未定義確認だけでは不十分。`onerror` 経由の実行は画像の読み込み失敗を待つため、投入直後の確認では間に合わない可能性がある。短い待機を挟んでから確認する。`dialog` 監視も併用して二重に張る。

**SC-3 の測り方** — 10,000 文字に `a*` を `g` 付きで適用すると 10,001 件の幅ゼロマッチが出るはずだが、FR-1.5 の上限 10,000 件で打ち切られる。`#truncated-notice` が表示されることも併せて確認する。「固まらない」と「打ち切りが働く」は別の要件なので両方見る。

**静的検証の実装** — Node 側でファイルを読んで正規表現でチェックする。`tests/static-check.js` として分け、`run.sh` から呼ぶ。

```js
// TC-1
const pure = ['src/evaluate.js', 'src/segments.js'];
for (const f of pure) {
  const src = fs.readFileSync(f, 'utf8');
  if (/\bdocument\b|\blocalStorage\b/.test(src)) fail(`TC-1: ${f} references DOM`);
}
```

**注意点**

- `page.goto('file://...')` の後に `localStorage.clear()` してから `reload()` する。`goto` 前に clear すると about:blank の localStorage を消してしまう
- `page.on('request')` は `file://` のリクエストも拾う。スキームで絞る
- 失敗を 1 件見つけても続行し、全シナリオを回してからまとめて報告する。最初の失敗で止めると 1 回の実行で得られる情報が減る
- 差し戻しが必要になった場合、このタスクを閉じずに該当タスク（003 / 004）を再オープンする判断が必要。その旨を進捗コメントに記録する
