# Task: ハイライト描画（DOM）

## Description

セグメント列を DOM 要素に変換する `RT.renderHighlight(container, segments)` を実装する。AD-4 が定めた分割の後半で、副作用のみを担う。「どこが何色か」の判断は 003 が済ませているため、このタスクは要素生成と挿入だけを行う。

XSS の防止線がここにある。`innerHTML` に文字列を組み立てて流し込むのではなく、`createElement` + `textContent` で組む（AD-4）。`textContent` に渡した文字列は markup として解釈される経路が存在しないため、エスケープ漏れという失敗モード自体が消える。NFR-2.1 の実質的な担保はこのタスクの責任。

## Acceptance Criteria

- [ ] `RT.renderHighlight(container, segments)` が `container` の既存の子要素を全て除去してから描画する（前回の結果が残らない）
- [ ] `kind: "plain"` のセグメントがテキストノードとして挿入される
- [ ] `kind: "match"` のセグメントが `class="rt-match"` を持つ要素として挿入され、`textContent` にマッチ文字列が入る
- [ ] `kind: "empty"` のセグメントが `class="rt-empty"` を持つ幅を持たない要素として挿入される（FR-2.4）
- [ ] 隣接する 2 マッチが視覚的に区別できる（それぞれ独立した要素で、CSS で境界が付く）（FR-2.3）
- [ ] 改行とインデント（連続空白）がテスト文字列の見た目通りに保持される（FR-2.5）
- [ ] セグメントが空配列のとき、コンテナが空になり例外を投げない
- [ ] マッチ 0 件（`"plain"` 1 件のみ）のとき、テスト文字列全体がハイライトなしで表示される（FR-2.6）
- [ ] **`innerHTML` / `outerHTML` / `insertAdjacentHTML` / `document.write` をいずれも使用しない**（grep で検証）
- [ ] テスト文字列に `<img src=x onerror="window.__XSS__=1">` を含めても、描画後に `window.__XSS__` が未定義（NFR-2.1）
- [ ] テスト文字列に `<script>window.__XSS__=1</script>` を含めても同様に未定義
- [ ] テスト文字列に含まれる `<`, `>`, `&` が、そのままの文字として画面に見える（`&lt;` のような文字参照が見えてはいけない）
- [ ] 1,000 セグメントの描画で `DocumentFragment` を使って一括挿入し、コンテナへの `appendChild` が 1 回で済む
- [ ] IIFE でラップされ `window.RT` 以外のグローバルを作らない（TC-2）

## Technical Details

**描画の骨格** — `DocumentFragment` に組んでから 1 回で挿入する。リフローの回数を抑え、NFR-1.1（100ms）の達成余地を作る。

```js
(function (RT) {
  RT.renderHighlight = function (container, segments) {
    container.textContent = "";               // 既存の子を除去
    var frag = document.createDocumentFragment();

    for (var i = 0; i < segments.length; i++) {
      var seg = segments[i];
      if (seg.kind === "plain") {
        frag.appendChild(document.createTextNode(seg.text));
      } else {
        var el = document.createElement("span");
        el.className = seg.kind === "empty" ? "rt-empty" : "rt-match";
        el.textContent = seg.text;            // markup は解釈されない
        frag.appendChild(el);
      }
    }
    container.appendChild(frag);
  };
})(window.RT);
```

**注意点**

- `container.textContent = ""` は既存の子を全て外す最も安価な方法。`innerHTML = ""` でも動くが、`innerHTML` を一切書かないという AC を満たすため使わない
- `rt-empty` は幅ゼロなので `textContent` が空。CSS で `border-left` などの幅を持たない視覚表現を与える（`styles.css` は 001 が用意する）
- 改行の保持はコンテナ側の `white-space: pre-wrap` で行う。JS 側で `<br>` に変換してはいけない（テキストノードのまま保つことが XSS 耐性の前提）
- 1,000 マッチ = 最大 2,001 セグメント。要素数がそのまま DOM ノード数になるため、`span` 以外の入れ子は作らない

**性能の測り方** — このタスクでは深追いしない。NFR-1.1 の計測は 009 が行い、未達なら差し戻す（epic のリスク節）。ここでは `DocumentFragment` による一括挿入という最低限の配慮だけ入れる。

**テストの置き場所** — `tests/unit.js` の `RT_TEST.suite("highlight", ...)` セクションに追記する。DOM を使うテストになるが、`unit.html` はブラウザで動くため `document.createElement("div")` をコンテナに使えばよい。
