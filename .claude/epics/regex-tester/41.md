# Task: 評価コア — RegExp 構築と exec 反復

## Description

パターン・フラグ・テスト文字列を受け取り、AD-2 のマッチレコード列に正規化して返す `RT.evaluate(pattern, flags, text)` を実装する。FR-1 の全項がここに閉じる。

このタスクの価値は「反復の危険を 1 箇所に閉じ込めること」にある。幅ゼロマッチによる無限ループ、`u` フラグ下でサロゲートペアを割る `lastIndex` 前進、`y` フラグの sticky 挙動、件数上限——これらは全て `exec()` 反復の制御であり、下流の 3 ビューには一切漏らさない（AD-3）。ここで漏らすと同じ判定が 3 箇所に散る。

DOM に触らない純粋関数として実装する。`document` も `localStorage` も参照しない（TC-1）。

## Acceptance Criteria

- [ ] `RT.evaluate(pattern, flags, text)` が実装され、成功時に `{ ok: true, matches: [...], truncated: boolean }` を返す（FR-1.6）
- [ ] 各マッチレコードが `index`, `end`, `match`, `groups`, `named` を持つ。`end` は `index + match[0].length` に一致する
- [ ] `groups` の各要素が `{ label: "$N", value, participated }` を持ち、`participated` が `value !== undefined` と一致する（FR-3.3 が要求する区別の実現）
- [ ] `named` が `(?<name>...)` の名前をラベルとして持ち、名前付きグループが無い場合は空配列になる
- [ ] `g` または `y` が有効なとき全マッチを列挙する。無効なとき先頭 1 件のみ返す（FR-1.2）
- [ ] 幅ゼロマッチ（`match[0].length === 0`）で `lastIndex` を手動で進め、無限ループしない（FR-1.3）
  - [ ] `a*` を `"bbb"` に `g` 付きで適用し、マッチ数が有限（文字数 + 1 = 4 件）になる
  - [ ] `(?:)` を任意の文字列に `g` 付きで適用して停止する
  - [ ] `^` を複数行文字列に `gm` 付きで適用し、行数と同じ件数になる
- [ ] `u` フラグ有効時、幅ゼロマッチの前進をコードポイント単位で行う（FR-1.4）
  - [ ] サロゲートペアを含む文字列（例 `"a😀b"`）に `u` + 幅ゼロパターンを適用し、不正な位置での再開や壊れた部分文字列が発生しない
- [ ] `y`（sticky）フラグ有効時、`lastIndex` の位置で一致しなければ即座に反復を終える
- [ ] マッチ数が 10,000 件に達したら収集を打ち切り `truncated: true` を返す（FR-1.5）
- [ ] `truncated: false` が上限未達のときに返る
- [ ] コンパイル失敗時に例外を投げず `{ ok: false, error: <message> }` を返す（FR-1.7）
  - [ ] `(`, `[`, `a{2,1}`, `\` の 4 パターンでいずれも `ok: false` になり、`error` が `SyntaxError` のメッセージを含む
- [ ] 空パターン（`""`）でも例外を投げない
- [ ] テスト文字列が空文字のとき、パターンが空文字にマッチするなら 1 件、しないなら 0 件を返す
- [ ] `document` および `localStorage` への参照が存在しない（TC-1、grep で検証）
- [ ] IIFE でラップされ `window.RT` 以外のグローバルを作らない（TC-2）

## Technical Details

**反復の骨格** — 安全装置を 1 つのループに集約する。

```js
(function (RT) {
  var MAX_MATCHES = 10000;

  RT.evaluate = function (pattern, flags, text) {
    var re;
    try {
      re = new RegExp(pattern, flags);
    } catch (e) {
      return { ok: false, error: String(e.message || e) };
    }

    var matches = [];
    var truncated = false;
    var global = flags.indexOf("g") !== -1 || flags.indexOf("y") !== -1;
    var unicode = flags.indexOf("u") !== -1;
    var m;

    while ((m = re.exec(text)) !== null) {
      matches.push(normalize(m));

      if (matches.length >= MAX_MATCHES) { truncated = true; break; }
      if (!global) break;

      if (m[0].length === 0) {
        re.lastIndex = advance(text, re.lastIndex, unicode);
        if (re.lastIndex > text.length) break;
      }
    }
    return { ok: true, matches: matches, truncated: truncated };
  };
})(window.RT);
```

**`advance` の実装** — `u` フラグ有効時はコードポイント単位。

```js
function advance(text, index, unicode) {
  if (!unicode) return index + 1;
  var cp = text.codePointAt(index);
  return index + (cp !== undefined && cp > 0xFFFF ? 2 : 1);
}
```

**注意点**

- `g` なしで `exec()` を呼ぶと `lastIndex` が更新されないため、`break` を忘れると無限ループする。上のコードでは `if (!global) break;` がそれを防ぐ
- `y` かつ `g` なしの場合も `lastIndex` は更新される。`global` の判定に `y` を含めているのはこのため
- グループ番号は `m.length - 1` 個。`m[1]` から `m[m.length - 1]` までを `$1`〜 に対応させる
- `m.groups` は名前付きグループが無いとき `undefined`。分解する前に存在確認する
- `participated` は `value !== undefined` で判定する。`""` は参加扱い

**テストの置き場所** — `tests/unit.js` の `RT_TEST.suite("evaluate", ...)` セクションに追記する。他タスクのセクションには触らない。
