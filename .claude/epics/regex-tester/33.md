# Task: Worker 隔離とタイムアウト

## Description

マッチと置換の実行を Web Worker に隔離し、規定時間を超えた実行を打ち切る層を実装する。US-6 に対応し、epic の AD-4 を具体化する。

破綻的バックトラッキング中の正規表現は、メッセージにも応答しないしフラグ変数も見ない。止める手段は `terminate()` しかない。したがってこの層の設計は「Worker を壊れたら捨てる資源として扱う」ことに尽きる。

## Acceptance Criteria

- [ ] `src/worker/regex-worker.js` が `src/logic/matcher.js` と `src/logic/replace.js` を import し、メッセージを受けて結果を返す
- [ ] `src/worker/worker-client.js` が `evaluate({pattern, flags, input, replacement})` を export し、Promise を返す
- [ ] 各リクエストに単調増加の ID が振られ、応答の ID が現在のリクエストと一致しない場合は破棄される
- [ ] 規定のタイムアウトを超えた実行で Worker が `terminate()` され、`{status:"timeout"}` が返る
- [ ] タイムアウト後の次のリクエストで Worker が自動的に再生成され、通常の結果が返る（ページ再読み込みを要さない）
- [ ] 連続してタイムアウトしても Worker がリークしない（terminate 済みの参照を保持し続けない）
- [ ] 前のリクエストが未完了のまま新しいリクエストが来た場合、古い結果で UI を上書きしない
- [ ] Worker の生成に失敗した場合（環境非対応等）にエラーが握り潰されず、呼び出し側が判別できる形で返る
- [ ] タイムアウト値が定数として定義され、変更が 1 箇所で済む
- [ ] 実ブラウザで `(a+)+$` に 30 文字以上の非マッチ文字列を当て、タイムアウトが発火し UI 操作が継続できることを確認した

## Technical Details

**メッセージ契約**:

```js
// main → worker
{ id: number, pattern: string, flags: string, input: string, replacement: string }

// worker → main
{ id: number, match: MatchOutcome, replace: {status:"ok",output:string}|{status:"error",message:string}|null }
```

置換文字列が未入力のとき `replace` を `null` にするか、常に実行するかを決めること。常に実行すると暴走パターンで 2 回分の時間を食うため、`replacement` が空なら Worker 側でスキップする方針が妥当。

**Worker の生成**: `new Worker(url, { type: "module" })` を使う。`type: "module"` を付けないと Worker 内で `import` が使えない。この指定を落とすと 29・31 のモジュールを再利用できず、コードの二重化を招く。

**タイムアウトの実装**:

1. リクエスト送出時に `setTimeout` を仕掛ける
2. 応答が先に来たらタイマーを解除
3. タイマーが先に発火したら `worker.terminate()`、Worker 参照を破棄、`{status:"timeout"}` で resolve
4. 次のリクエスト時に Worker が無ければ生成する（遅延生成）

**ID による古い応答の破棄**: terminate しなかった場合でも、デバウンスをすり抜けた古いリクエストの応答が後から届き得る。ID を照合して現在のリクエスト以外を捨てる。この判定を省くと、入力が速いときに古い結果が一瞬表示される。

**テストについて**: この層は Worker API に依存するため `node --test` では覆えない。ロジック部分（ID 照合、タイムアウト後の再生成）を Worker API から分離できるなら分離してテストを書く。分離が困難な場合は、実ブラウザでの確認をもって受け入れとし、その手順を記録に残すこと。
