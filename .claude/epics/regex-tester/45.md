# Task: 置換プレビュー

## Description

置換文字列を適用した結果を専用領域に表示する `RT.renderReplace(container, pattern, flags, text, replacement)` を実装する。FR-5 の全項がここに閉じる。

**`$1` や `$<name>` の展開を自前で実装しない。** `String.prototype.replace` にそのまま委譲する。自前実装すると、`$$`（リテラル `$`）や `$&`（全体一致）、存在しないグループ番号の扱いといった仕様の細部でブラウザの挙動と乖離する。PRD の問題 5「既存ツールは別方言のエンジンで動いており結果が一致しない」を、このツール自身が再現してしまう。

## Acceptance Criteria

- [ ] `RT.renderReplace(container, pattern, flags, text, replacement)` が置換結果を `container` に表示する（FR-5.1）
- [ ] 置換の展開が `String.prototype.replace` に委譲されており、`$` 記法を自前で解釈していない（コードレビューで確認）
- [ ] `$1`〜`$9` が番号付きグループに展開される
- [ ] `$<name>` が名前付きグループに展開される
- [ ] `$&` が全体一致に展開される
- [ ] `$$` がリテラルの `$` 1 文字になる
- [ ] `g` が OFF のとき先頭 1 件のみ置換される（FR-5.3 の前提となる `g` 挙動）
- [ ] `g` が ON のとき全マッチが置換される
- [ ] 置換文字列が空文字のとき、マッチ部分が削除された結果が表示される
- [ ] パターンがコンパイルエラーのとき、置換結果領域が空状態になる（FR-5.3）
- [ ] 置換結果の表示がテスト文字列の入力値（`#test-text` の `value`）を変更しない（FR-5.4）

- [ ] 置換文字列に `<img src=x onerror="window.__XSS__=1">` を入れても `window.__XSS__` が未定義（NFR-2.1）
- [ ] テスト文字列に markup を含めても同様に未定義
- [ ] 改行と連続空白が置換結果でも見た目通り保持される
- [ ] 幅ゼロマッチを生むパターン（`a*` に `g`）で置換しても無限ループせず結果が返る
- [ ] IIFE でラップされ `window.RT` 以外のグローバルを作らない（TC-2）

## Technical Details

**委譲の骨格** — `RegExp` の構築だけ自分で行い、展開はブラウザに任せる。

```js
(function (RT) {
  RT.renderReplace = function (container, pattern, flags, text, replacement) {
    container.textContent = "";

    var re;
    try {
      re = new RegExp(pattern, flags);
    } catch (e) {
      return;                       // FR-5.3: エラー時は空状態
    }

    var output;
    try {
      output = text.replace(re, replacement);
    } catch (e) {
      return;                       // 置換文字列側の異常も空状態に倒す
    }

    container.textContent = output;  // markup は解釈されない
  };
})(window.RT);
```

**注意点**

- `text.replace(re, replacement)` は `re` の `lastIndex` を副作用で変えるため、評価コアが使う `RegExp` インスタンスを共有してはいけない。ここで新しく `new RegExp` する（上のコードはそうなっている）
- 幅ゼロマッチの無限ループは `String.prototype.replace` 側で処理されるため、このタスクで対策は不要。`"bbb".replace(/a*/g, "X")` は仕様通り有限回で終わる。AC で確認するのは「委譲が正しく効いていること」
- `container.textContent = output` は改行をそのまま保持する。見た目の保持はコンテナ側の `white-space: pre-wrap`（001 の `styles.css`）に依存する
- `replacement` に関数を渡す機能は作らない（PRD にない）
- `y`（sticky）フラグ付きの `replace` はブラウザ実装依存の挙動があるが、委譲しているため乖離は生じない。特別扱いしない

**評価コアとの関係** — このタスクは `RT.evaluate` を呼ばない。置換はマッチレコードを必要とせず、`String.prototype.replace` が内部で走査する。呼び出し側（008）が `#replacement` の入力とパターン・フラグを渡すだけでよい。この独立性のおかげで 002 と完全に並行できる。

**テストの置き場所** — `tests/unit.js` の `RT_TEST.suite("replace", ...)` セクションに追記する。
