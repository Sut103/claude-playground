# Task: グループ表描画

## Description

マッチレコード列からキャプチャグループの表を描画する `RT.renderGroups(container, result)` を実装する。FR-3 の全項がここに閉じる。

このビューが解決するのは PRD の問題 2「番号付きグループと名前付きグループが混在すると、配列インデックスと `groups` オブジェクトを目で突き合わせる作業になる」。両者を同じ表に並べ、対応を目で追えるようにする。

表示上の要点は `undefined` と `""` の区別（FR-3.3）。評価コアが `participated` フラグで判定済みなので、このタスクは受け取った真偽値に応じた表記を出すだけでよい。ここで `=== undefined` を再判定してはいけない（AD-2）。

## Acceptance Criteria

- [ ] `RT.renderGroups(container, result)` が `container` の既存の子を除去してから描画する
- [ ] マッチごとに、マッチ番号・開始インデックス・全体一致文字列を含む行が表示される（FR-3.1）
- [ ] 番号付きグループが `$1`, `$2`, ... のラベルと捕捉文字列の対で表示される（FR-3.2）
- [ ] 名前付きグループが `(?<name>...)` の名前をラベルとして表示される（FR-3.2）
- [ ] `participated: false` のグループが、空文字列を捕捉したグループと**区別できる表記**で表示される（例: `(未参加)` と `""`）（FR-3.3）
- [ ] `participated: true` かつ `value === ""` のグループが、空文字を捕捉したことが分かる表記になる
- [ ] グループを持たないマッチでも、マッチ番号・インデックス・全体一致の行は表示される
- [ ] `result.matches` が空配列のとき、空状態のメッセージを表示する（FR-3.4）
- [ ] `result.ok === false`（パターンエラー）のとき、空状態のメッセージを表示し、直前の成功結果を残さない（FR-3.4 / US-4）
- [ ] `result.truncated === true` のとき、件数が打ち切られたことが表から分かる（または呼び出し側が `#truncated-notice` に出す前提で、表自体は打ち切り後の件数を正しく表示する）
- [ ] 全ての文字列を `textContent` で挿入し、`innerHTML` / `outerHTML` / `insertAdjacentHTML` を使用しない（grep で検証）
- [ ] 捕捉文字列に `<img src=x onerror="window.__XSS__=1">` を含むマッチレコードを渡しても `window.__XSS__` が未定義（NFR-2.1）
- [ ] 1,000 マッチのレコード列を渡しても描画が完了し、`DocumentFragment` で一括挿入される
- [ ] IIFE でラップされ `window.RT` 以外のグローバルを作らない（TC-2）

## Technical Details

**表の構造** — `<table>` を使い、マッチごとにヘッダ行 + グループ行を出す。あるいはマッチごとに `<section>` を作る。どちらでもよいが、1,000 マッチで DOM ノードが爆発しない構造を選ぶ。

```js
(function (RT) {
  RT.renderGroups = function (container, result) {
    container.textContent = "";

    if (!result || !result.ok || !result.matches || result.matches.length === 0) {
      var msg = document.createElement("p");
      msg.className = "rt-empty-state";
      msg.textContent = !result || result.ok === false
        ? "パターンにエラーがあります"
        : "マッチなし";
      container.appendChild(msg);
      return;
    }

    var frag = document.createDocumentFragment();
    for (var i = 0; i < result.matches.length; i++) {
      frag.appendChild(buildMatchRow(i, result.matches[i]));
    }
    container.appendChild(frag);
  };
})(window.RT);
```

**未参加グループの表記** — `participated` をそのまま使う。

```js
function formatValue(g) {
  if (!g.participated) return "(未参加)";
  if (g.value === "") return '""（空文字）';
  return g.value;
}
```

`"(未参加)"` という文字列を実際に捕捉したグループと見分けが付かなくなる懸念があるが、`participated: false` の行には CSS クラスも付けて視覚的にも区別する（`class="rt-unparticipated"`）。表記だけに頼らない。

**注意点**

- ラベル `$1` の番号は 1 始まり。評価コアが `label` を埋めて渡すので、このタスクで番号を計算し直さない
- 名前付きグループは番号付きグループとしても現れる（`(?<x>a)` は `$1` かつ `x`）。両方表示するのが正しい。重複ではなく別の参照方法として並べる
- 全体一致が長い場合の省略表示は行わない（PRD にそういう要件はない）。CSS の `overflow` に任せる

**テストの置き場所** — `tests/unit.js` の `RT_TEST.suite("groups", ...)` セクションに追記する。`tests/fixtures.js` の `unparticipatedGroup` と `namedGroup` をそのまま入力に使える。
