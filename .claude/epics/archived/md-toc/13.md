# Task: TOC splicing between marker comments

## Description

Implement the routine that injects a rendered TOC back into a Markdown document. `splice_toc(text, toc)` locates the `<!-- toc -->` and `<!-- /toc -->` marker comments in the document, replaces everything between them with the supplied TOC block, and returns the resulting document as a new string. It does not read or write files — it is a pure string-to-string transformation, which is what lets both `--in-place` and `--check` share it: one writes the return value, the other compares it against the original.

The two behaviors that carry the most risk are byte-for-byte preservation of everything outside the markers, and idempotency. Splicing a document whose embedded TOC is already current must return a string identical to the input, because `--check` decides staleness by exactly that comparison. If splicing perturbs whitespace, line endings, or the marker lines themselves, `--check` reports every document as stale forever.

When either marker is missing, the function raises a marker-specific error naming the expected markers rather than returning a best-effort result. The CLI turns that error into exit code 2 with the file left untouched.

## Acceptance Criteria

- [ ] `splice_toc(text, toc)` replaces the content between `<!-- toc -->` and `<!-- /toc -->` with the generated TOC and returns the new document.
- [ ] Every byte before the opening marker and every byte after the closing marker is preserved exactly, including trailing whitespace, blank lines, and the presence or absence of a final newline.
- [ ] The marker lines themselves survive the splice unchanged and remain in the output, so the document can be spliced again.
- [ ] Splicing a document whose marker region already contains the identical TOC returns a string equal to the input (idempotency), so a second `--in-place` run is a no-op.
- [ ] A missing `<!-- toc -->` marker, a missing `<!-- /toc -->` marker, or both missing raises a marker-specific error whose message names both expected markers.
- [ ] A closing marker appearing before the opening marker is rejected with the same marker error rather than producing a scrambled document.
- [ ] An empty marker region (the two markers adjacent) is filled correctly on the first splice.
- [ ] Only the first marker pair is treated as the TOC region; marker-looking text inside the body after the closing marker is left alone.
- [ ] Unit tests in `tests/test_splice.py` cover replacement, preservation, idempotency across two consecutive splices, and each missing-marker case.

## Technical Details

Owns exactly two paths:

- `md_toc/splice.py`
- `tests/test_splice.py`

Public surface:

```python
splice_toc(text: str, toc: str) -> str
```

plus the marker-absence exception type raised from this module and imported by the CLI to map onto exit code 2. The marker constants `<!-- toc -->` and `<!-- /toc -->` are defined here as module-level constants so the CLI and the tests reference one source of truth.

Implementation is a plain string search for the two markers (not a regex over the whole document), splitting the text into prefix, region, and suffix. The prefix ends with the opening marker line, the suffix begins with the closing marker line, and only the region between them is rebuilt as `\n + toc + \n`. Building the result by concatenating the untouched prefix and suffix is what makes byte-for-byte preservation structural rather than something to test for after the fact. Idempotency then follows from the renderer being deterministic: the same headings produce the same `toc` string, which reassembles to the same region.

No filesystem access, no imports outside the standard library.
