# Task: CLI wiring, flags, and exit-code contract

## Description

Build the command-line shell that assembles the pure core into the `md-toc` tool. This is the only module in the package that touches the filesystem: it reads the target file, calls the parser, slug generator, renderer, and splicer, and then either prints, writes, or compares depending on the flags.

The command surface is `md-toc <file> [--in-place] [--check] [--min-level N] [--max-level N]`. `--in-place` and `--check` are mutually exclusive — argparse enforces this so the conflict is reported as a usage error rather than as a runtime surprise. With neither flag, the tool prints the TOC to stdout and leaves the file untouched, which is the PRD's safety guarantee that no invocation modifies a file unless `--in-place` is passed.

`--check` and `--in-place` are the same computation with different endings: both call `splice_toc` on the file's content with a freshly rendered TOC. `--in-place` writes the result back; `--check` compares it against what was read and exits 0 if identical, 1 if not, printing a message that names the stale file. Sharing the splice call is what makes check-mode agreement with in-place mode structural — check mode can never disagree with what in-place would have produced, because it asks the same question.

Exit codes are centralized here: 0 success, 1 stale TOC under `--check`, 2 usage or I/O error. Missing files, unreadable files, and the marker-absence error from task 13 all map to 2 with a message on stderr.

## Acceptance Criteria

- [ ] `md-toc FILE` with no flags prints a nested Markdown list to stdout and leaves the file byte-for-byte unmodified.
- [ ] `--in-place` replaces the content between `<!-- toc -->` and `<!-- /toc -->` and writes the file back, preserving everything outside the markers.
- [ ] A second consecutive `--in-place` run leaves the file byte-identical to after the first run.
- [ ] `--check` exits 0 when the embedded TOC matches what would be generated, and 1 when it does not.
- [ ] `--check` never writes to the target file, on either outcome.
- [ ] On a stale `--check`, the message identifies the file that is stale.
- [ ] `--in-place` and `--check` together are rejected by argparse as a usage error with exit code 2, and no file is read or written.
- [ ] `--min-level` and `--max-level` bound which heading levels appear in the output, in every mode.
- [ ] A nonexistent or unreadable path exits 2 with a message on stderr and nothing on stdout.
- [ ] A file lacking the marker comments under `--in-place` exits 2, names the expected markers, and leaves the file unmodified.
- [ ] `python3 -m md_toc FILE` behaves identically to the console invocation.

## Technical Details

Owns exactly three paths:

- `md_toc/cli.py`
- `md_toc/__main__.py`
- `tests/test_cli.py`

Command-line surface:

```
md-toc <file> [--in-place] [--check] [--min-level N] [--max-level N]
```

Public surface in `md_toc/cli.py`:

```python
build_parser() -> argparse.ArgumentParser
main(argv: list[str] | None = None) -> int
```

`main` returns the exit code rather than calling `sys.exit`, so tests can assert on the integer directly without trapping `SystemExit`. `md_toc/__main__.py` is a three-line shim: `sys.exit(main())`.

Mutual exclusion uses `parser.add_mutually_exclusive_group()`, which yields argparse's own exit status 2 for the conflict — matching the required usage-error code without a special case. `--min-level` and `--max-level` are `type=int` and are passed straight through to `extract_headings`.

Mode dispatch after reading the file with `pathlib.Path.read_text(encoding="utf-8")`:

- default: render and print to stdout, return 0
- `--in-place`: `splice_toc(text, toc)`, `write_text`, return 0
- `--check`: `splice_toc(text, toc)`, compare to `text`, return 0 if equal else print the file path as stale to stdout and return 1

`OSError` from read or write, and the marker-absence error imported from `md_toc.splice`, are caught at the top of `main` and turned into a stderr message plus return 2. Tests drive `main` with argv lists against files in a `tempfile.TemporaryDirectory`, asserting both the return code and the on-disk bytes.
