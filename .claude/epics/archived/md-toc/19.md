# Bug: anchor slugs collapse whitespace runs, diverging from GitHub

## Context

Found while implementing issue #16, "GitHub anchor slug generation". The
implementing agent flagged the divergence rather than letting it pass silently.

## Description

`slugify` collapses runs of whitespace into a single hyphen. GitHub does not.
Because punctuation is stripped *before* spaces are converted, a heading like
`C++ / C#` leaves two spaces where the punctuation was, and GitHub turns each
into its own hyphen.

The defect originates in the task specification, not the implementation: task
16.md states "runs of whitespace collapse to one hyphen", which contradicts the
PRD. PRD functional requirement 4 says "lowercase, spaces to hyphens, punctuation
stripped" with no collapsing, and the Constraints section names GitHub's anchor
algorithm as the target dialect. The implementation faithfully follows 16.md, so
the bug was introduced during epic decomposition and inherited downstream.

This matters beyond cosmetics: the anchor is a link target. A slug that does not
match GitHub's produces a TOC entry whose link is dead on GitHub — the exact
failure the PRD's problem statement sets out to eliminate.

## Steps to Reproduce

```python
from md_toc.slug import slugify
slugify("C++ / C#", {})
```

## Expected vs Actual

- Expected: `c--c` (GitHub's result — `++`, `/`, and `#` are removed, and each
  remaining space becomes its own hyphen)
- Actual: `c-c`

Also affected: any heading containing consecutive spaces, or punctuation
surrounded by spaces.
