# Task: ストア層 — 読み書き、原子的置換、ID 採番

## Description

`taskcli/store.py` を実装する。Markdown ファイルと `Document` オブジェクトの間の入出力を担う層である。

この層の中心にあるのは AD-3 の要求だ。タスクファイルは CLI の専有物ではなく、人間がエディタで見出しやメモを書き足す場所でもある。したがって `Document` は「パース済みのタスク行」と「そのまま維持する非タスク行」を **順序を保ったまま混在させて** 保持しなければならない。CLI 操作の結果として、人間が手で書いた行が消えたり位置が入れ替わったりしてはならない。

併せて AD-4（一時ファイル + `os.replace` による原子的書き込み）と AD-2（ID をファイルから毎回導出する採番）を実装する。

触るファイルは `taskcli/store.py` とその専用テストファイルのみであり、004（表示層）・005（コマンド層）と並行して実装できる。

## Acceptance Criteria

**`Document` モデル**

- [ ] `Document` がファイルの全行を **元の順序どおり** に保持する。要素はタスク行（`Task`）と非タスク行（原文の文字列）の混在である
- [ ] `Document` から「タスクのみ」を取り出す手段（例: `tasks` プロパティ）があり、ファイル内の出現順を保つ
- [ ] `Document` に対するタスクの追加・完了・削除の操作が、非タスク行の位置関係を壊さずに行える

**`load(path) -> Document`**

- [ ] 既存ファイルを読み、タスク行を `parse_line` で `Task` に変換し、それ以外の行は原文のまま保持する
- [ ] **ファイルが存在しない場合、例外を送出せず空の `Document` を返す**（US-1: 初期化コマンドを別途叩く必要がない）
- [ ] 空ファイル（0 バイト）を読んだ場合も空の `Document` を返す
- [ ] 見出し（`## 今週`）、空行、通常の段落、チェックボックスのない箇条書きが、すべて非タスク行として原文のまま保持される
- [ ] **パースできないタスク行の扱い（FR-8）**: 標準エラーに警告を出し、その行を非タスク行として原文のまま保持し、残りの行の処理を継続する。異常終了しない
  - [ ] 警告メッセージに行番号が含まれ、どの行が問題かを利用者が特定できる
  - [ ] 警告は stderr に出る。stdout を汚さない（`list` の出力をパイプで扱えるようにするため）
- [ ] 重複した ID を含むファイルを読んでも `load` は失敗しない（警告は出してよい）。ファイルは人間が手編集しうるため、読み取り時点で異常終了させない

**`save(path, document)`**

- [ ] `Document` の各要素を元の順序で書き出す。タスクは `format_line` で、非タスク行は原文のまま
- [ ] **原子的書き込み（AD-4 / NFR-3）**: 一時ファイルを **保存先と同一ディレクトリ** に作成し、書き込み・フラッシュ後に `os.replace` で目的パスへ置換する。`/tmp` など別ファイルシステム上の一時ファイルを使わない（`os.replace` の原子性は同一ファイルシステム内でのみ保証されるため）
- [ ] 置換前に中断した場合でも、元ファイルが従前の内容のまま残る。中間状態の一時ファイルが目的パスに現れない
- [ ] 書き込み中に例外が発生した場合、一時ファイルを後始末する（残骸を放置しない）
- [ ] 出力ファイルは末尾に改行を 1 つ持ち、改行コードは `\n` に統一される
- [ ] 保存先の親ディレクトリが存在しない場合の挙動が定義され、テストされている

**`next_id(document) -> int`**

- [ ] ファイル内の既存タスクの ID の最大値 + 1 を返す（AD-2）
- [ ] タスクが 1 件もない `Document` に対して `1` を返す
- [ ] **ID を保存する状態ファイルを作らない**。採番は毎回 `Document` から導出される
- [ ] **削除しても他タスクの ID は変わらない（FR-5）**: ID が 1, 2, 3 のタスクがある状態で ID 2 を削除しても、1 と 3 はそのまま。その後の `next_id` は 4 を返す（2 は再利用されない）
- [ ] 最大 ID のタスクを削除した場合も ID を再利用しない設計上の限界を認識し、テストで現在の挙動を明示的に固定する（最大 ID を削除すると次の採番はその ID になる — これは AD-2 の「ファイルから毎回導出する」という決定の帰結である。挙動をテストで文書化する）

**往復（round-trip）**

- [ ] **非タスク行が load / save の往復で元の位置に残る**: 見出し → タスク → 空行 → メモ → タスク の順に並んだファイルを `load` して即 `save` したとき、行の内容と順序がすべて保存される
- [ ] タスクを 1 件追加して保存したとき、既存の非タスク行の相対位置が変わらない
- [ ] タスクを 1 件削除して保存したとき、削除された行だけが消え、他の行（タスク・非タスクとも）は位置も内容も変わらない
- [ ] パース不能行を含むファイルを load / save したとき、その行が原文のまま同じ位置に残っている

## Technical Details

- **`Document` の内部表現**: 行のリストを 1 本持ち、各要素が `Task` か `str` のどちらかである（タグ付きの小さなラッパでもよい）。「タスクだけのリスト」と「非タスク行だけのリスト」を別々に持って後で合成する設計は、順序の再現に行番号の管理が必要になり、AD-3 の要求に対して脆い。単一のリストで順序をそのまま持つ方が、往復テストの保証が自明になる。

- **`os.replace` を使う理由（AD-4）**: `os.rename` は Windows で既存ファイルがあると失敗するが、`os.replace` は上書きを含めて POSIX / Windows の両方で定義されており、同一ファイルシステム上で原子的である。`shutil.move` は跨ファイルシステム時にコピーへフォールバックするため原子性が失われる。一時ファイルは `tempfile.NamedTemporaryFile(dir=<保存先と同じディレクトリ>, delete=False)` または `tempfile.mkstemp(dir=...)` で作る。`dir` を保存先と揃えることが原子性の前提条件である。

- **耐久性の範囲**: 置換前に `flush()` + `os.fsync()` を行うかは判断が要る。fsync はクラッシュ耐性を上げるが、単一ユーザーのローカル CLI という前提（PRD の Constraints）に対しては過剰にもなりうる。本タスクでは fsync を入れる方針とし、コストが問題になる規模ではない（NFR-4 は 1000 件で 1 秒以内であり、1 回の fsync は十分収まる）。

- **警告の出力先と形式**: FR-8 の警告は `sys.stderr` に出す。ストア層が `print(..., file=sys.stderr)` を直接呼ぶか、警告を `Document` に添えて返して呼び出し側が出すかは実装判断だが、**ストア層が出力を持つ場合はテストで stderr を捕捉できる形にする**こと。テストからは `contextlib.redirect_stderr` で検証する。

- **エンコーディング**: 読み書きとも UTF-8 を明示する（`encoding="utf-8"`）。ロケール依存の既定エンコーディングに任せない。日本語のタスク本文が主要ユースケースであり、環境差で壊れてはならない。

- **改行の扱い**: 読み取りは `splitlines()` 相当で行に分解し、行末の改行は保持しない。書き出し時に `"\n".join(...) + "\n"` で再構成する。これにより CRLF のファイルを読んでも LF に正規化される。

- **`load` は検証しない**: 重複 ID の検出やタスクの整合性チェックはストア層の責務外とする。読み取りは可能な限り成功させ、判断は上位に委ねる — AD-3 の「パーサは寛容、書き込みは厳格」という原則をストア層まで引き延ばした形である。

- **本タスクの範囲外**: 並び順・`OVERDUE` 判定・出力整形（004）、argparse とファイルパス解決（005）。`TASK_CLI_FILE` の解決は 005 が行い、ストア層は渡された `path` をそのまま扱う。

## Dependencies

- 先行タスク: 002（`Task`、`parse_line`、`format_line` が確定していること）
- 並列: 004（表示層）・005（コマンド層）と同時に実行できる。本タスクが触るのは `taskcli/store.py` とその専用テストファイルのみで、004 の `taskcli/render.py`・005 の `taskcli/cli.py` とファイルが重ならない
- 後続: 006（結線と E2E）が本タスクの `load` / `save` / `next_id` を使う
- 外部依存: なし（`os`、`tempfile`、`pathlib`、`sys` — いずれも標準ライブラリ）
