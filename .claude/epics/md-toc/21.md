# Bug: UTF-8 BOM silently swallows the first heading

## Context
Found by the acceptance suite in issue #17.

## Description
`read_text(encoding="utf-8")` leaves the byte-order mark as `\ufeff` on the
first character of the document. The parser's `^#` anchor therefore does not
match the first line, and the document's first heading is dropped from the TOC
with no error.

Silent omission is the dangerous part: the tool reports success and emits a TOC
that is simply missing an entry.

## Steps to Reproduce
```
printf '\xef\xbb\xbf# Title\n\n## Alpha\n' > bom.md
python3 -m md_toc bom.md
```

## Expected vs Actual
- Expected: entries for both `# Title` and `## Alpha`
- Actual: only `- [Alpha](#alpha)`

## Acceptance Criteria
- [ ] Bug is fixed: read with `encoding="utf-8-sig"` so the BOM is consumed
- [ ] A BOM-prefixed document yields all its headings, first one included
- [ ] A document without a BOM is unaffected
- [ ] Under `--in-place`, the BOM is preserved in the written file
- [ ] A regression test covers the BOM case
- [ ] `python3 -m unittest discover` passes with zero failures
