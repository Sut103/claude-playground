# Task: Heading extraction with fenced-code suppression

## Description

Implement the document scanner that turns Markdown source text into an ordered list of `Heading` values. It recognizes ATX headings (`#` through `######`), suppresses heading-like lines that appear inside fenced code blocks, and honors the `--min-level` / `--max-level` bounds the CLI will pass through.

This is a line-based scanner, not a Markdown AST walk. The epic's architecture decision is explicit here: only ATX headings and fenced-code state are in scope, so a single pass carrying one "inside fence" boolean is sufficient and avoids a parser dependency the PRD forbids. Fence state is evaluated before heading detection on every line, because a `#` inside a fenced block is never a heading.

The function is pure — it takes text and returns values, touching no files. That is what lets every acceptance criterion below be tested without fixtures on disk.

## Acceptance Criteria

- [ ] `extract_headings` parses all six ATX levels, `#` through `######`, returning the correct `level` for each.
- [ ] Returned headings preserve document order.
- [ ] The leading `#` run and the whitespace following it are stripped from `title`; trailing whitespace is stripped too.
- [ ] A line inside a ``` ``` ``` fenced block is never returned as a heading, even when it starts with `#`.
- [ ] A line inside a `~~~` fenced block is likewise never returned as a heading.
- [ ] A fence opened with one delimiter is not closed by the other: `~~~` does not terminate a ``` ``` ``` block, and vice versa.
- [ ] An unterminated fence at end of file suppresses all remaining lines rather than raising.
- [ ] `min_level` excludes headings shallower than the bound; `max_level` excludes headings deeper than it.
- [ ] Defaults `min_level=1, max_level=6` include every heading in a document.
- [ ] A `#` with no following space (e.g. `#hashtag`) is not treated as a heading.
- [ ] A document with no headings returns an empty list rather than raising.
- [ ] A 10,000-line document is scanned in well under one second, supporting the PRD's performance requirement.
- [ ] `tests/test_parser.py` covers each criterion above as a distinct `unittest` test method.

## Technical Details

Paths owned by this task, and no others:

- `md_toc/parser.py`
- `tests/test_parser.py`

Signature implemented:

```python
def extract_headings(text: str, min_level: int = 1, max_level: int = 6) -> list[Heading]:
```

`Heading` is imported from `md_toc.types` (task 12). Split the input with `str.splitlines()` and iterate once. For each line:

1. Test the fence toggle first. A fence opener/closer is a line whose stripped form begins with three or more backticks or three or more tildes. Record which character opened the fence and only let that same character close it.
2. If inside a fence, continue without further inspection.
3. Otherwise match the ATX pattern — a run of one to six `#` characters, then at least one space, then the title. Use a compiled `re` pattern at module scope so the 10,000-line case does not recompile per line.
4. Apply the `min_level` / `max_level` filter before appending.

Closing `#` runs (`## Title ##`) should be trimmed from the title so the slug generator in task 16 does not have to. Standard library only: `re` and `dataclasses` via the imported type.

## Dependencies
