# Task: GitHub anchor slug generation

## Description

Implement the anchor dialect: convert a heading's title text into the fragment identifier GitHub would generate for it, so that every TOC entry links to a live anchor rather than a dead one.

The transformation is lowercase, strip punctuation, spaces to hyphens. The part that actually carries risk is duplicate disambiguation — two headings with the same text must produce `#title`, `#title-1`, `#title-2`, in document order. That state cannot live inside the function, so callers pass a `seen` dictionary that accumulates occurrence counts across the whole document.

The epic flags this as one of the two highest-risk areas in the feature, on the grounds that duplicate-heading handling is the part most likely to diverge from GitHub's real behavior. It therefore gets its own dedicated test module rather than being folded into an end-to-end pass.

## Acceptance Criteria

- [ ] `slugify` lowercases the title: `"Getting Started"` becomes `getting-started`.
- [ ] Spaces become single hyphens; runs of whitespace collapse to one hyphen.
- [ ] Punctuation is stripped rather than replaced: `"What's New?"` becomes `whats-new`.
- [ ] Existing hyphens in the title are preserved.
- [ ] The first occurrence of a title yields a bare slug with no numeric suffix.
- [ ] The second occurrence of the same title yields that slug with `-1` appended; the third yields `-2`.
- [ ] The `seen` dict is mutated in place so successive calls across one document keep counting correctly.
- [ ] Two different titles that normalize to the same slug are disambiguated against each other, not treated as distinct.
- [ ] Passing a fresh empty `seen` resets numbering, so slugs for one document never leak into another.
- [ ] A title that reduces to the empty string after stripping does not raise.
- [ ] Non-ASCII letters are retained in lowercase form rather than discarded.
- [ ] `tests/test_slug.py` covers each criterion above as a distinct `unittest` test method, including an explicit three-way duplicate case.

## Technical Details

Paths owned by this task, and no others:

- `md_toc/slug.py`
- `tests/test_slug.py`

Signature implemented:

```python
def slugify(title: str, seen: dict[str, int]) -> str:
```

Algorithm, in order: lowercase via `str.lower()`; remove characters that are neither word characters, whitespace, nor hyphens using a compiled `re` pattern; collapse and convert whitespace runs to single hyphens. Then consult `seen`: if the base slug is absent, store `0` and return the base unchanged; if present, increment the stored count and return `f"{base}-{count}"`. Mutating `seen` in place is the contract — the caller owns the dict lifetime, one per document.

Use `re` with Unicode semantics (Python 3's default for `\w`) so accented characters survive rather than being stripped, matching GitHub. Compile patterns at module scope. Standard library only; this module imports nothing from the rest of the package, which is what makes it safely concurrent with task 14.
