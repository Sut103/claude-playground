# Task: 結線と E2E テスト — 実際のコマンド実行での通し確認

## Description

003（ストア層）／004（表示層）／005（コマンド層）が並列に仕上げた 3 つの層を結線し、通しで動く 1 本の CLI にする。

具体的には、005 が `cli.py` 内に置いたシーム（`_load` / `_save` / `_render` 等の間接層）を、実際の `taskcli.store` / `taskcli.render` の呼び出しへ置き換える。そのうえで、CLI を**サブプロセスとして起動する** E2E テストを追加し、実ファイルに対する一連の操作が期待どおりの標準出力・終了コード・ファイル内容を生むことを確認する。

E2E はモックを使わない。`tmp_path` に本物の Markdown ファイルを置き、`TASK_CLI_FILE` でそこを指し、`python -m taskcli ...` を `subprocess.run` で叩く。層内部の単体テストでは捕まえられない結線ミス（引数の受け渡し、`None` の扱い、終了コードの取りこぼし）を検出することが目的である。

このタスクは 003 / 004 / 005 のすべてが揃ってから着手する。並列実行はしない。

## Technical Details

**サブプロセスでの起動.** `subprocess.run([sys.executable, "-m", "taskcli", ...], env={...}, cwd=tmp_path, capture_output=True, text=True)` の形を取る。`sys.executable` を使うことで、テストを走らせている Python と同じ処理系が確実に選ばれる。`env` は `os.environ` のコピーに `TASK_CLI_FILE` を上書きしたものを渡し、`PYTHONPATH` にリポジトリルートを通す（あるいは editable install 済みなら不要）。

`capture_output=True, text=True` で stdout / stderr を文字列として取得し、`result.returncode` と併せてアサートする。

**シーム置き換えの進め方.** 005 のテストはシームを `monkeypatch` で差し替えて書かれている。結線後もそれらの単体テストが通り続けるよう、シーム関数の**シグネチャは維持**し、中身だけを実装呼び出しに変える。シグネチャを変えざるを得ない場合は 005 のテストも併せて更新する（この時点では並列作業が終わっているので編集して構わない）。

**ファイル不変のアサート.** 「ファイルを変更しない」は、操作前後で `path.read_bytes()` を比較するのが最も確実である。行数や部分文字列の比較では、末尾改行や空白の差異を見逃す。

**手編集テストの書き方.** 手編集は `path.write_text()` で書き換えた文字列を与えることで再現する。「CLI が生成した内容を読み、行のリストに変換し、見出しと自由記述行を挿入し、タスク行を入れ替えて書き戻す」という手順にすると、実際の人間の操作に近く、かつ決定的になる。

**依存の性質.** 003 / 004 / 005 の**すべて**が完了していないと着手できない。1 本でも欠けるとシームを実装へ置き換えられない。
