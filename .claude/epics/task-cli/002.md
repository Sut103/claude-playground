# Task: パーサ層 — Task モデルと行の相互変換

## Description

`taskcli/parser.py` を実装する。Markdown の 1 行と `Task` オブジェクトを相互に変換する層であり、他のどの層にも依存しない。

**本エピックのクリティカルパスである。** AD-1 の行フォーマットに関する設計判断がここに集中しており、ここで書式が変われば 003（ストア層）・004（表示層）・005（コマンド層）はすべてやり直しになる。したがって本タスクは並列化せず、単独で完了させてから後続を開始する。

AD-1 の行フォーマット:

```markdown
- [ ] リファクタする `#3` `!high` `@docs` `@refactor` `~2026-08-20`
- [x] README を書く `#1` `!mid`
```

| 記号 | 意味 |
| --- | --- |
| `#N` | タスク ID |
| `!high` / `!mid` / `!low` | 優先度 |
| `@tag` | タグ（0 個以上） |
| `~YYYY-MM-DD` | 期限 |

## Acceptance Criteria

**`Task` モデル**

- [ ] `Task` データクラスが `id: int`、`text: str`、`done: bool`、`priority: Priority`、`tags: list[str]`、`due: date | None` を持つ
- [ ] `Task` 同士の等価比較が全フィールドの値で行われる（`@dataclass` の既定の `__eq__` で足りる）。後述の往復テストがこれに依存する

**`parse_line(line) -> Task | None`**

- [ ] `- [ ] リファクタする \`#3\` \`!high\` \`@docs\` \`@refactor\` \`~2026-08-20\`` を、`id=3`、`text="リファクタする"`、`done=False`、`priority=high`、`tags=["docs","refactor"]`、`due=date(2026,8,20)` として解釈する
- [ ] `- [x]` はチェック済み（`done=True`）として解釈される。`- [X]`（大文字）も同様に受け付ける
- [ ] **メタデータのないタスク行**（例: `- [ ] メモを書く \`#7\``）がパースでき、`priority` が既定値 `mid`、`tags` が空リスト、`due` が `None` になる
- [ ] **タグは指定順を保存する**: `\`@b\` \`@a\` \`@c\`` は `["b","a","c"]` となり、ソートも重複除去も行わない
- [ ] `text` からメタデータ部分は除去され、前後の空白がトリムされる。本文中に `#` や `@` を含む文字列（例: `- [ ] issue #42 を @alice に聞く \`#5\``）は、バッククォートで囲まれていない限りメタデータとして解釈されず本文に残る
- [ ] **パースできない行は `None` を返す。例外を送出しない**。次のいずれも `None` を返すこと:
  - [ ] 見出し行（`## 今週`）、空行、通常の段落テキスト
  - [ ] チェックボックスのない箇条書き（`- ふつうの項目`）
  - [ ] ID メタデータ `\`#N\`` を欠くチェックリスト行（ID なしはタスクとして識別できない）
  - [ ] 不正な優先度（`\`!urgent\``）を含む行
  - [ ] 不正な日付を含む行 — `\`~2026-13-45\``（月・日が範囲外）、`\`~2026-02-30\``（存在しない日）、`\`~tomorrow\``、`\`~2026/08/20\``（区切りが異なる）、`\`~26-08-20\``（桁数が異なる）
- [ ] 日付の検証は `datetime.strptime(s, "%Y-%m-%d").date()` による厳密パースであり、`2026-13-45` のような値を通さない

**`format_line(task) -> str`**

- [ ] `Task` を AD-1 の書式の 1 行に戻す。メタデータの並びは `#id` → `!priority` → `@tag...`（登録順） → `~due` に固定する
- [ ] `due` が `None` の場合、`~` のメタデータを出力しない。`tags` が空の場合、`@` のメタデータを出力しない
- [ ] `priority` は既定値 `mid` であっても常に明示的に出力する（往復の安定と手編集時の可読性のため）
- [ ] 出力行に改行文字を含めない（改行の付与はストア層の責務とする）

**往復（round-trip）**

- [ ] `parse_line(format_line(t)) == t` が、次のすべての `Task` について成立する: メタデータ全部入り / タグ 0 個 / タグ 3 個 / 期限なし / `done=True` / 各優先度（high・mid・low） / 日本語本文 / バッククォートを含まない記号混じりの本文
- [ ] `format_line(parse_line(s))` が、正規形で書かれた入力行 `s` に対して `s` と一致する（メタデータ順が正規順の入力に限る）
- [ ] 往復でタグの順序が変わらないことを、順序が辞書順と異なるケース（`["z","a","m"]`）で確認する

## Technical Details

- **`parse_line` が `None` を返し、例外を送出しない理由（AD-3）**: パーサ層は寛容に設計する。ファイルには CLI が書いていない行 — 手書きの見出し、メモ、通常の箇条書き — が当然に混ざっており、それらは「エラー」ではなく「タスク行ではない行」である。パーサがここで例外を投げると、呼び出し側は正常系の制御フローに `try/except` を敷くことになり、「タスク行でない」と「壊れたタスク行」を区別できなくなる。`None` は単に「この行は `Task` として解釈できなかった」という事実だけを返し、**それをどう扱うか（警告するか、原文のまま保持するか、無視するか）の判断はストア層に委ねる**。FR-8 の「警告して読み飛ばし、原文は残す」という挙動は 003 で実装される。

- **実装方針**: 行全体を 1 本の巨大な正規表現でマッチさせるのではなく、(1) チェックボックス接頭辞 `- [ ]` / `- [x]` の判定 → (2) 末尾のバッククォート囲みトークンを右から順に切り出す → (3) 各トークンを記号ごとに分類・検証 → (4) 残りを `text` としてトリム、という段階的な処理にする。段階を分けることで、どの段階で失敗したかがテストで切り分けやすくなり、本文中の `#`/`@` との衝突も自然に避けられる（バッククォートで囲まれ、かつ行末側に連続しているトークンだけが対象になる）。

- **優先度の表現**: `Priority` は `enum.Enum` とし、`high` / `mid` / `low` の 3 値を持つ。004（表示層）が優先度降順ソートを行うため、順序比較のための数値（high=3, mid=2, low=1 など）を列挙値に持たせるか、明示的な順序マップを公開する。どちらにするかを本タスクで決め、公開 API として固定する — 004 がこれに依存する。

- **未知のメタデータトークン**: `` `?foo` `` のような未知の記号で始まるバッククォートトークンは、判定に迷いを残さないため「不正」として扱い `None` を返す。将来の拡張はその時点で書式を決めればよく、いま曖昧に受け流すと往復で情報が失われる。

- **`Task` は不変にしなくてよい**: 005（コマンド層）の `done` コマンドが `done` フラグを書き換える。`frozen=True` にすると差し替え用の生成コードが増えるだけなので、通常の可変データクラスとする。

- **本タスクの範囲外**: ファイル I/O、ソート、`OVERDUE` 判定、argparse。それぞれ 003 / 004 / 005 に属する。

## Dependencies

- 先行タスク: 001（パッケージ構造とテストランナーが確定していること）
- 後続タスク: 003 / 004 / 005 がすべて本タスクの公開 API（`Task`、`Priority`、`parse_line`、`format_line`）に依存する。本タスクを完了させてから 3 本を並列起動する
- 外部依存: なし（`dataclasses`、`enum`、`datetime`、`re` — いずれも標準ライブラリ）
