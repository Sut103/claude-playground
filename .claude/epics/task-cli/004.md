# Task: 表示層 — 並び順、期限状態の判定と整形

## Description

`taskcli/render.py` を実装する。002 で確定した `Task` を入力に取り、`list` コマンドが標準出力へ書き出す文字列を組み立てる層である。

責務は 3 つに限定する。

1. **並び替え** — US-3 の表示順（優先度降順 → 期限昇順 → 期限なしが末尾）を実現する
2. **期限状態の判定** — US-4 の `OVERDUE` / `DUE TODAY` を導出する
3. **整形** — 1 タスクを 1 行のプレーンテキストへ変換する

フィルタリング（`--all` / `--priority` / `--tag` / `--overdue`）そのものはコマンド層（005）の責務であり、この層は「与えられた `Task` の並びを整えて文字列にする」ことだけを行う。ただし `--overdue` がフィルタ条件として使えるよう、期限状態の判定関数は単体で呼び出せる公開関数として切り出す。

ファイル入出力は一切行わない。`store.py` にも `cli.py` にも触れない。したがって 003 / 005 と完全に並行して実装できる。

## Acceptance Criteria

- [ ] `sort_tasks(tasks) -> list[Task]` が、優先度降順（high → mid → low）で並べる
- [ ] 同一優先度内では期限の昇順で並ぶ（古い期限が先）
- [ ] 期限が `None` のタスクは、同一優先度グループの**末尾**に来る
- [ ] 並びは安定である — 優先度も期限も等しい 2 件は、入力順を保つ（`sorted` のキー指定で実現し、複数回の `sort` で崩さない）
- [ ] `due_state(task, today=None) -> str | None` が、`today` を**引数として受け取る**。既定値の解決は `today or date.today()` の形で関数内部で行い、モジュールグローバルや `datetime` のモンキーパッチには一切依存しない（AD-5）
- [ ] 期限が `today` より前かつ `done` が False のタスクに対し `due_state` が `"OVERDUE"` を返す
- [ ] 期限が `today` と等しいタスクに対し `due_state` が `"DUE TODAY"` を返す
- [ ] 期限が `today` より後、期限が `None`、または `done` が True のタスクに対しては `None` を返す（完了済みは期限切れとして扱わない）
- [ ] `render_task(task, today=None) -> str` が 1 行の文字列を返し、ID・チェック状態・本文・優先度・タグ・期限・期限状態を含む
- [ ] `render_list(tasks, today=None) -> str` が、並び替えたうえで各行を改行連結して返す。タスクが 0 件のときは空文字または明示的な「タスクなし」相当の 1 行を返し、例外を投げない
- [ ] すべてのテストが `today=date(2026, 8, 20)` のように**固定日付を渡して**書かれており、実行日が変わってもパス・フェイルが変化しない
- [ ] 出力に ANSI エスケープシーケンスが含まれない。カラー出力と TTY 判定は PRD の Out of Scope であり、`sys.stdout.isatty()` の参照も行わない
- [ ] 変更したファイルが `taskcli/render.py` と対応するテストファイルのみである（`git status` で確認する）

## Technical Details

**並び替えのキー設計.** 優先度を数値に写像する（high=0, mid=1, low=2 のように、昇順ソートで high が先頭に来る向きに取る）。期限は `None` を末尾に送る必要があるため、`(due is None, due or date.min)` のようなタプルをキーにする。ブール値は False < True なので、期限ありが先、なしが後になる。全体のキーは `(priority_rank, due is None, due_or_sentinel)` の 1 本のタプルで組み、`sorted` を 1 回だけ呼ぶ。Python の `sorted` は安定なので、キーが完全に等しい要素の入力順は保存される。

**期限状態の判定.** シグネチャは `def due_state(task, today: date | None = None) -> str | None:` とする。既定値の位置に `date.today()` を直接書くと**モジュール import 時に評価されて固定される**ため、必ず `None` を既定値にして関数本体で解決する。これは AD-5 の意図（テストの日付非依存化）を満たすうえで本質的な点である。

**完了済みの扱い.** US-4 の受け入れ基準は「期限が本日より前**かつ未完了**」を OVERDUE と定めている。`done` が True のタスクは期限を過ぎていても `OVERDUE` を付けない。`DUE TODAY` も同様に未完了のみを対象とする。

**整形の形.** 表示行の例を 1 つ決め打ちし、テストの期待値として固定する。ID と本文は必須、優先度・タグ・期限は持つものだけ出す。期限状態は行末に付ける。`OVERDUE` / `DUE TODAY` は目印なので、他の要素と視覚的に区切れる位置に置く。

**触らないもの.** `store.py`（003 が実装中）と `cli.py`（005 が実装中）には読み書きとも行わない。`render.py` は `parser.py` の `Task` のみを import する。
