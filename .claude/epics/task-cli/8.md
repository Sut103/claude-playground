# Task: コマンド層 — argparse の骨格と 4 サブコマンド

## Description

`taskcli/cli.py` を実装する。argparse のサブパーサとして `add` / `list` / `done` / `rm` の 4 コマンドを定義し、それぞれを終了コードを返す関数として実装する（FR-1〜FR-4、FR-9）。

**このタスクの範囲は「コマンド層のインターフェース」までである。** ストア層（003）と表示層（004）は同時並行で実装されているため、`store.py` / `render.py` を直接編集してはならない。編集すると 003 / 004 とファイル衝突を起こし、並列実行の前提が壊れる。

そのため本タスクでは、ストア・表示への呼び出しを**薄いシーム（seam）越し**に書く。具体的には `cli.py` の内部にモジュールレベルの間接層（例: `_load()` / `_save()` / `_render()` といった関数、あるいは呼び出し先を保持する小さなインジェクションポイント）を置き、テストではそこを差し替えて引数解析と分岐ロジックだけを検証する。実際の `store.py` / `render.py` への結線は 006 が行い、そこでシームは実装呼び出しに置き換わる。

検証の主眼は「引数がどう解釈され、どの終了コードが返るか」であり、ファイルが実際にどう書き換わるかは 006 の E2E テストが受け持つ。

## Acceptance Criteria

**パーサの骨格**

- [ ] `build_parser() -> argparse.ArgumentParser` が、`add` / `list` / `done` / `rm` の 4 サブコマンドを持つパーサを返す
- [ ] サブコマンドを省略した場合、ヘルプ相当を出して非ゼロ終了する（無言で成功しない）
- [ ] 未知のサブコマンドを与えた場合、argparse の標準挙動で非ゼロ終了する
- [ ] `main(argv=None) -> None` が `build_parser()` で解析し、各コマンド関数の戻り値（int）を `sys.exit` に渡す（FR-9）。コマンド関数自身は `sys.exit` を呼ばず、int を `return` する

**add（FR-1、US-1）**

- [ ] `add <text>` が本文を必須位置引数として受け取る
- [ ] `--priority` が `{high, mid, low}` の `choices` に制限され、省略時の既定値が `mid` になる
- [ ] 範囲外の優先度（例 `--priority urgent`）は argparse が非ゼロ終了で拒否する
- [ ] `--tag` が `action="append"` で繰り返し指定でき、未指定時は空リスト相当として扱われる（`None` がそのまま下流に漏れない）
- [ ] `--due YYYY-MM-DD` を受け取り、不正な日付（`2026-13-45` / `tomorrow` など）はエラーメッセージを出して非ゼロ終了し、**ファイルを一切変更しない**（US-4）。検証は書き込みより前に行う
- [ ] 成功時、割り当てられた ID を標準出力に表示し 0 を返す（US-1）

**list（FR-2、US-3）**

- [ ] 既定（オプションなし）では未完了タスクのみを対象とする
- [ ] `--all` で完了済みを含める
- [ ] `--priority` で優先度を絞り込む
- [ ] `--tag` でタグを絞り込む
- [ ] `--overdue` で期限切れのみを絞り込む
- [ ] 複数のフィルタを同時指定した場合、**AND** で結合される（例: `--priority high --tag docs` は両方を満たすタスクのみ）
- [ ] 該当タスクが 0 件でも終了コードは 0（「見つからない」はエラーではない）

**done / rm（FR-3、FR-4、US-5）**

- [ ] `done <id>` が ID を整数として受け取り、タスクを完了状態に変える。行はファイルから**削除しない**
- [ ] すでに完了しているタスクへの `done` は、標準エラーに警告を出しつつ終了コード **0** を返す（冪等、US-5）
- [ ] `rm <id>` が該当タスクを行ごと削除する
- [ ] `done` / `rm` とも、存在しない ID に対しては**非ゼロ終了**し、ファイルを変更しない（US-5）
- [ ] 整数として解釈できない ID（`abc` など）は argparse が非ゼロ終了で拒否する

**ファイルパス解決（FR-6）**

- [ ] 環境変数 `TASK_CLI_FILE` が設定されていればそのパスを使う
- [ ] 未設定なら `./TASKS.md` を使う
- [ ] パス解決は独立した関数（例 `resolve_path()`）として切り出され、環境変数を差し替えた単体テストで両分岐が検証されている

**境界の遵守**

- [ ] 変更したファイルが `taskcli/cli.py` と対応するテストファイルのみである（`git status` で確認する）。`taskcli/store.py` と `taskcli/render.py` は**作成も編集もしない**
- [ ] 実行時 import が標準ライブラリと `taskcli` 内モジュールのみである（NFR-1）

## Technical Details

**シームの置き方.** `cli.py` から見たストア／表示の呼び出し口を、モジュールレベルの薄い関数に集約する。例えば `_load(path)` / `_save(path, doc)` / `_render(tasks)` を定義し、本タスクの段階では最小限の実装（あるいは `NotImplementedError` を投げないダミー）とする。各コマンド関数はこの関数群だけを経由し、`store` / `render` を直接 import しない。テストでは `monkeypatch.setattr` でこの関数群を差し替え、引数解析・分岐・終了コードを検証する。006 でここが実装呼び出しに置き換わる。

この方針の目的は、006 まで `store.py` / `render.py` に触れずに済ませることである。003 / 004 が同じファイルを編集中なので、ここで先回りして書くと衝突する。

**終了コードの規約.** 成功は 0。利用者起因のエラー（不正な日付、存在しない ID）は非ゼロ（1 を基本とする）。argparse 自身が弾く入力（不正な `choices`、非整数の ID、未知のサブコマンド）は argparse の既定である 2 で終了してよい。コマンド関数は int を返すだけで、終了処理は `main()` に集約する（FR-9）。

**日付の検証位置.** `--due` の検証は「解析直後・書き込み前」に行う。argparse の `type=` に検証関数を与えると argparse が非ゼロ終了で弾いてくれるため、ファイル変更が起きようがない。この構造にすれば US-4 の「ファイルを変更しない」が自然に満たされる。

**`--tag` の正規化.** `action="append"` の既定値は `None` である。そのまま下流へ渡すと `None` に対する反復でエラーになるため、コマンド関数の入口で `args.tag or []` に正規化する。

**警告の出力先.** FR-8 と US-5 の警告はいずれも**標準エラー**へ出す。標準出力はタスク一覧と ID の表示に限定し、パイプ処理を壊さない。
