# Task: プロジェクト構造とテスト基盤のセットアップ

## Description

`taskcli` パッケージの骨格と、テストを実行できる最小構成を用意する。以降のすべてのタスク（002〜007）はこのディレクトリ構成とテストランナーの上に実装されるため、本タスクが構造を先に確定させる。

同時に、エピックの Dependencies に記載された未確定事項 — **pytest がこの環境にインストールできるかどうか** — をここで決着させる。クラウドセッションの `pip install` はプロキシ経由であり失敗しうる。失敗した場合は標準ライブラリの `unittest` に切り替え、その判断を本ファイルの Acceptance Criteria とリポジトリ内に記録する。以降のタスクは「どちらを使うか」を再検討しない。

実装コードはこのタスクでは書かない。各モジュールは空ファイル（または docstring のみ）として置き、002 以降が中身を埋める。

## Acceptance Criteria

- [ ] 次のファイルが存在する: `taskcli/__init__.py`、`taskcli/parser.py`、`taskcli/store.py`、`taskcli/render.py`、`taskcli/cli.py`（後者 4 つは docstring のみの空モジュールでよい）
- [ ] `tests/` ディレクトリが存在し、`tests/__init__.py`（または pytest の rootdir 設定）によりテストが import エラーなく発見される
- [ ] リポジトリルートから `python -c "import taskcli"` が成功する（`sys.path` の追加操作なしに）
- [ ] `pyproject.toml`（または同等の最小設定）が存在し、パッケージ名・Python 要求バージョン `>=3.10`・テストパスの設定を含む。実行時依存は空であること
- [ ] **テストランナーの決定を明示的に記録する**: `pip install pytest` を実行し、成否を確認する
  - [ ] 成功した場合 → pytest を採用。`pyproject.toml` に dev 依存として pytest を記載する
  - [ ] 失敗した場合（プロキシ由来のエラーを含む）→ 標準ライブラリ `unittest` に切り替え、`python -m unittest discover -s tests` で実行できる構成にする
  - [ ] どちらを採用したか、および失敗時は失敗の内容（コマンドとエラー出力の要点）を、本タスクの完了報告と `README` 相当の記述に残す
- [ ] `python -m pytest` が **import エラーなく完走**し、「0 tests collected」または単一の自明なパスするテスト（例: `tests/test_smoke.py` の `assert True`）を報告して終了コード 0 で終わる
  - [ ] unittest にフォールバックした場合は、`python -m unittest discover -s tests` が同等の結果（失敗 0 件、終了コード 0）を返すことをもってこの基準を満たすものとする
- [ ] `.gitignore` に `__pycache__/`、`*.pyc`、`.pytest_cache/` が含まれる
- [ ] 実行時 import に標準ライブラリ以外が現れないこと（この時点では空モジュールなので自明だが、方針として確認する）

## Technical Details

- **パッケージレイアウト**: フラット配置（リポジトリルート直下に `taskcli/` と `tests/`）とする。`src/` レイアウトは import パスの設定が余分に必要になり、標準ライブラリのみという方針に対して構成コストが見合わない。
- **モジュール分割はエピックの層構成に一致させる**: `parser.py`（パーサ層）、`store.py`（ストア層）、`cli.py`（コマンド層）、`render.py`（表示層）。003/004/005 が並列実行できる前提は「触るファイルが重ならない」ことなので、この 1 層 1 ファイルの対応をここで固定する。
- **`pyproject.toml` の最小内容**: `[project]` に `name`、`version`、`requires-python = ">=3.10"`、`dependencies = []`。pytest を採用する場合のみ `[project.optional-dependencies]` の `dev` に追加する。ビルドバックエンドは設定するが、パッケージのインストール（`pip install -e .`）は必須としない — ルートからの実行で import できれば十分である。
- **unittest フォールバック時の互換性**: 002 以降のテストは、フォールバックした場合でも書き換えが最小になるよう、`assert` ベースの関数テストではなく `unittest.TestCase` を使う方針に統一する。pytest は `TestCase` をそのまま収集できるため、pytest 採用時もこの書き方で動く。この方針を本タスクで決めておくことで、後から片方に寄せ直す手戻りを避ける。
- **`tmp_path` への依存に注意**: pytest の `tmp_path` フィクスチャは unittest では使えない。フォールバックの可能性がある以上、テスト内の一時ディレクトリは標準ライブラリの `tempfile.TemporaryDirectory` を使う方針とし、これも本タスクで決定して記録する。
